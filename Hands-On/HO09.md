# ${\color{orange}\text{HO09: Armazenamento e Organização de Dados}}$

## ${\color{orange}\text{ Conceitos Iniciais: Armazenamento em Memória }}$

BDs são armazenados fisicamente em meios (mídias) de armazenamento computacional, formando uma **hierarquia**, em que dados residem e transitam, sendo que a hierarquia reflete a distância do meio à CPU.

1. **Memória primária** → fica próxima e é operada diretamente pela CPU
2. **Memória secundária** → distante e não é operada pela CPU
3. **Memória terciária** → muito distante e não é operada pela CPU

    * Os programas residem e são executados em memória primária.
    * Bancos de Dados são geralmente grandes e persistem em memória secundária.
    * SGBD transfere partes do Banco entre memórias de acordo com a necessidade.

Existe uma correlação entre capacidade de armazenamento, a velocidade de transferência e o custo em meios de armazenamento.

* **Capacidade de armazenamento** → é a quantidade de dados (bytes) que podem ser **armazenados** na memória.
* **Velocidade de transferência** → é a quantidade de dados (bits) que podem ser **transferidos** para a memória ou da memória por uma unidade de tempo (segundo).
* **Custo** → é a **unidade monetária** ($) por quantidade de dados (bytes) que podem ser armazenados na memória.

A relação entre essas unidades se dá por meio da seguinte relação (simbólica):

<div align="center">

$Custo = \frac{1}{Velocidade}$

$Velocidade = \frac{1}{Capacidade}$

</div>

Isso significa que *Custo ⨯ Velocidade* e *Velocidade ⨯ Capacidade* são unidades inversamente proporcionais.

Esta imagem representa a Hierarquia de Memória e Armazenamento de um computador. Ela ilustra o modo como os dados fluem desde a sua entrada pelo utilizador até ao seu processamento (CPU).

1. **CPU Register (Registos do Processador)**:

    * No topo. Fica dentro do próprio processador.
    * É a memória mais rápida e cara que existe, mas com capacidade minúscula (bytes).

2. **Cache (Nível 1, Nível 2, etc.)**:

    * Memória ultra-rápida situada junto ao núcleo do processador.
    * Guarda cópias dos dados mais frequentemente usados pela RAM para evitar que o CPU perca tempo de espera.

3. **RAM (Physical RAM & Virtual Memory)**:

    * A memória principal de trabalho.
    * Physical RAM: Os módulos físicos de memória.
    * Virtual Memory: Espaço do disco rígido reservado para fingir que é RAM quando a RAM física enche.
    * É a fronteira da área de armazenamento temporário (*Volatile/Temporary Storage*). Se o computador desligar, tudo o que está do nível da RAM para cima desaparece.

4. **Storage Device Types (Dispositivos de Armazenamento)**:

    * Inclui *ROM/BIOS*, discos rígidos (*Hard Drive/SSD*), pens *USB* (*Removable Drive*) e armazenamento em rede (*Network Storage*).
    * É a área de armazenamento permanente (*Non-Volatile/Permanent Storage*). Os dados continuam guardados mesmo sem energia elétrica. É **muito mais lenta** do que a RAM e a Cache, mas oferece **capacidades enormes** (*Terabytes*) a custos baixos.

5. **Input Sources (Fontes de Entrada)**:

    * Na base da pirâmide estão os periféricos (teclado, *mouse*, câmara, microfone, mídias externas).
    * São a origem dos dados primários que entram no sistema para serem processados, é a comunicação física entre a máquina e o usuário.

Quanto mais para o **topo**, **mais rápida** é a memória, **menor é a sua capacidade** e **mais cara** ela custa por Byte. Enquanto que mais para a **base**, **maior a lentidão** da memória, **aumenta a sua capacidade** e **mais barata** ela é.

A memória é volátil (temporária) do topo até a RAM, onde é rápida, mas perde os dados ao desligar, e é não volátil (permanente) da RAM até a base da pirâmide, onde é mais lenta porém mantém os dados gravados permanentemente.

* **Relação com consultas SQL**: Quando se executa uma consulta SQL em disco, o SGBD lê os dados do *Storage* (base) e carrega-os na *RAM/Cache* (topo) para os poder processar rapidamente. Por isso, evitar ler dados desnecessários no disco (como filtros adequados no WHERE) é a chave para o desempenho do código.

### ${\color{orange}\text{Custo ⨯ Velocidade}}$

A velocidade da memória não é representada por uma única unidade, mas sim por três métricas principais:

1. **Largura de Banda / Taxa de Transferência (Volume por Tempo)**: Mede o volume de dados que a memória consegue transferir por segundo.
    * GB/s (Gigabytes por segundo) ou MB/s.
    * Outra unidade é *bps* (bits por segundo), como Mbps (Megabits por segundo)
    * Refere-se comumente à SSDs, HDDs e barramentos de memória RAM.

2. **Frequência / Velocidade de Clock (Ciclos por Tempo)**: Mede quantos ciclos de trabalho a memória consegue realizar por segundo. 
    * Unidades principais: MT/s (*Megatransfers* por segundo) ou MHz (*Megahertz*).
    * Geralmente refere-se à memória RAM (ex: DDR4-3200 MT/s, DDR5-6000 MT/s).

3. **Tempo de Acesso e Latência (Atraso na Resposta)**: Mede o tempo decorrido desde o momento em que o CPU pede um dado até ao momento em que esse dado começa a ser entregue.
    * Nanosegundos ($ns$): Usado para Registos ($< 1\text{ ns}$), Caches L1/L2 ($1\text{ a }5\text{ ns}$) e RAM ($10\text{ a }50\text{ ns}$).
     * Milisegundos ($ms$): Usado para Discos Rígidos/HDDs ($5\text{ a }15\text{ ms}$).
     * Latência da RAM (CL / CAS Latency): Medida em ciclos de clock (ex: CL16, CL30).

Em arquitetura de computadores e na indústria de hardware, o custo da memória é quase sempre representado pela métrica de Custo por Unidade de Capacidade:

<div align="center">

$$\text{Custo de Memória} = \frac{\text{Preço Total}}{\text{Capacidade em Bytes}} \quad \left(\text{ex: } \frac{\$}{\text{GB}} \text{ ou } \frac{\$}{\text{TB}}\right)$$

</div>

2. **CACHE** 

    * Memória eletrônica
    * Níveis → L1 a L3 (Padrão comercial)
    * L1:
        - Localização: Dentro do núcleo
        - Velocidade (latência): Ultra-rápida ($\approx 1\text{--}2\text{ ns}$)
        - Velocidade (largura de banda): geralmente entre 1,5 TB/s e 3 TB/s por núcleo
        - Capacidade Típica: 32 KB a 128 KB por core
    * L2:
        - Localização: Ao lado do núcleo
        - Velocidade (latência): Muito rápida ($\approx 3\text{--}10\text{ ns}$)
        - Velocidade (largura de banda): taxas médias entre 500 GB/s e 1,5 TB/s por núcleo
        - Capacidade Típica: 512 KB a 2 MB por core
    * L3:
        - Localização: Fora dos núcleos (no chip)
        - Velocidade (latência): Rápida ($\approx 10\text{--}20\text{ ns}$)
        - Velocidade (largura de banda): faixa de 800 GB/s a 2 TB/s no total do chip
        - Capacidade Típica: 16 MB a 128 MB+ (total)
    * Níveis → L0 a L4 (engenharia)
        - Rápida → L1 ≈ 6 Tbps
        - Pequena → L4 ≈ 128 MB
        - Cara → L0 > 100 R$/MB
        - Acelera a execução de instruções de programa (pré-busca e *pipelining*)

Um core (ou núcleo) é a unidade de processamento independente localizada dentro do processador (CPU). Pode ser visto como o "cérebro" individual encarregado de executar as instruções dos programas e realizar cálculos matemáticos e lógicos.

Antigamente, os processadores tinham apenas 1 único core (*single-core*), o que significava que o computador só conseguia processar uma tarefa de cada vez (as outras tarefas tinham de esperar na fila).

Dessa forma, a utilização de múltiplos *cores* é o que permite o paralelismo de processamento e otimização de tempo gasto.

Enquanto a **CPU** (processador) é a peça física (o chip de silício) que encaixa na *motherboard* (placa mãe), o **core** (núcleo) é cada uma das *unidades de processamento individuais* presentes dentro desse chip.

A diferença fundamental entre a memória eletrônica e a memória magnética está no princípio físico de gravação e na presença ou ausência de partes móveis.

Mecanismo de Gravação:

* **Memória Eletrônica (Solid-State)**: Armazena os dados através de **cargas elétricas em componentes microscópicos** (transistores e capacitores) dentro de chips de silício. Exemplos: RAM, Cache, Pen Drive, SSD (Flash).

* **Memória Magnética**: Armazena os dados **alterando a polaridade magnética (norte/sul) de partículas metálicas** na superfície de um disco ou fita. O "0" ou "1" é definido para onde o campo magnético está apontando. Exemplos: HD (Disco Rígido), Fita Magnética, Disquete.

Partes Móveis:

* **Memória Eletrônica**: Não possui nenhuma peça móvel. Funciona de forma 100% silenciosa e é chamada de "estado sólido" (daí o nome SSD - Solid State Drive).

* **Memória Magnética**: Depende de motores e engrenagens. Em um HD, existem pratos de metal girando em alta velocidade e uma "agulha" (cabeçote de leitura) que se move fisicamente sobre o disco para ler ou gravar os dados.

A gravação em memória ótica (como CDs, DVDs e Blu-rays) funciona através da utilização de um feixe de laser para criar e ler alterações microscópicas na superfície de um disco revestido por um material refletor.

Este processo cria um padrão de depressões microscópicas chamadas poços (*pits*) e áreas planas intocadas chamadas planícies (*lands*). Nas mídias regraváveis (como os CD-RW ou DVD-RW), o laser simplesmente altera o estado de uma liga metálica especial entre **cristalino** (refletor) e **amorfo** (opaco), permitindo que o processo seja revertido.

### ${\color{orange}\text{ Armazenamento em Memória }}$

* Dados **transientes** → persistem em memória por um período limitado de tempo,
apenas durante a execução do programa (são voláteis).
* Dados **persistentes** → permanecem em memória por longos períodos de tempo,
sendo acessados e processados repetidamente durante esse período (não são voláteis)

No projeto físico, DBAs (*Database Administrator*) e projetistas devem escolher as melhores técnicas de organização de dados para garantir equilíbrio entre custo e desempenho, atendendo aos requisitos funcionais e operacionais do BD.

Geralmente só a parte necessária do BD é processada, sendo responsabilidade do SGBD garantir que:

1. A parte seja transferida da memória secundária para a primária.
2. A CPU processa os dados em memória primária adequadamente.
3. Os dados processados serão transferidos de volta à memória secundária.

Na prática um BD é armazenado em disco, pois apresentam excelente relação custo-benefício, ainda
mais vantajosa que outros tipos de memória secundária.

### ${\color{orange}\text{ Armazenamento em Disco}}$

A unidade mínima de transferência de dados entre disco e memória primária é denominada **Bloco** ou **Página**.

* Possuem um tamanho fixado, geralmente entre 512B a 8KB, que não pode ser alterado dinamicamente.
* São separados nas trilhas por lacunas de tamanho fixo que incluem dados de controle, como ponteiro para o bloco subsequente.
* pode ser acessado **aleatoriamente** pelo seu **endereço de hardware**, denominado **endereço de bloco**.
* Hardwares controladores de disco usam o endereço do bloco para transferir o
bloco do disco para um **buffer em memória primária**.

O ***buffer*** é a área reservada contígua em memória primária.

* **Leitura (*Input*)** → o bloco é copiado para buffer.
* **Escrita (*Output*)** → o buffer é sobrescrito no bloco.

A **leitura e a escrita (I/O)** no disco possui um **tempo de transferência** de dados determinada por pelo menos 3 tempos:

* **Tempo de Busca** → tempo necessário para **posicionar o cabeçote** de leitura e escrita na trilha do endereço de bloco.
* **Tempo de Latência** → é o **atraso rotacional** necessário para o disco girar até o ponto de leitura/escrita.
* **Tempo de Transferência de Bloco** → tempo necessário para os dados transacionaram do *buffer* para a memória principal e vise-versa.
	* Transferir múltiplos blocos consecutivos na mesma trilha (ou cilindro) elimina tempos de busca e latência acumulados, tornando a transferência mais eficiente (busca sequencial).

Uma técnica de otimização aplicada é o ***duplo buffering***.

* Enquanto o controlador de disco transfere dados de, ou para, um buffer, a CPU processa dados em outro buffer, garantindo um processamento paralelo.
* Elimina tempos de busca e latência para todas as transferências de bloco, com exceção da primeira.

### ${\color{orange}\text{ Alocação de Blocos }}$

A forma como os blocos são alocados em disco impacta o desempenho de I/O.

* **Alocação Contígua** → blocos armazenados consecutivamente, podem ser processados rapidamente com duplo *buffering*, porém a expansão é difícil caso ocorra alteração de dados, o que implica em realocações.

*  **Alocação por Ligação** → cada bloco contém um ponteiro para o próximo como uma lista encadeada. Facilita a expansão, mas a leitura/escrita são lentas pela inviabilização do duplo *buffering*.

* **Alocação por Segmento** → agrupa blocos consecutivos em segmentos (*clusters*) e cada segmento contém um ponteiro para o próximo segmento, tornando o duplo *buffering* viável, agilizando o I/O ao mesmo tempo que facilita expansão.

* **Alocação Indexada** → blocos especiais de índice são criados contendo ponteiros para blocos de dados. Rápido I/O com busca sendo efetuada em blocos de índice, que podem ter
alocação contígua ou por segmento (duplo *buffering*). Fácil expansão, com realocações ocorrendo em blocos de índice. Também permite buscas mais eficientes e ordenações específicas.

## ${\color{orange}\text{ Conceitos Iniciais: Organização de Dados }}$

**Blocagem**, ou **Fator de Bloco**, ou **Fator de Blocagem** de um arquivo refere-se a **quantidade de registros** deste arquivo que cabem em um bloco de disco.

Esse fator é determinado pelo tamanho do bloco dividido pelo tamanho médio dos registros:

<div align="center">

${F = \left \lfloor \frac{\textit{tamanho do bloco (bytes)}}{\textit{tamanho do registro (bytes)}}\right \rfloor}$

ou

${F = \left \lfloor \frac{\textit{ t }}{\textit{ r }}\right \rfloor}$

</div> 

**Obs.**: o fator de blocagem deve ser um número inteiro de registros, além disso, não se pode arredondar para mais, uma quantidade de memória que não se tem, por isso usa-se o piso.

Quando o tamanho do registro é suficientemente grande (mais que a metade do tamanho do bloco), no caso, quando o fator de blocagem for baixo, o espalhamento pode ser mais vantajoso para evitar desperdício de espaço.

Esse espaço não usado pode ser detectado por:

<div align="center">

${U = t - (F \times r)}$

</div>

**Obs.**: O resultado não é 0, é o resto retirado pelo piso dado pelo fator de blocagem.

Um arquivo quase nunca cabe em um único bloco. O fator de blocagem ajuda a determinar a quantidade de blocos necessários para armazenar um arquivo, isso sabendo a quantidade de registros do arquivo (**n**).

<div align="center">

${B = \left \lceil \frac{n}{F}\right \rceil}$

</div>

**Obs.**: A quantidade de blocos para também deve ser um valor inteiro, além disso, arredonda-se para cima garantindo que não haja falta de espaço para gravar o arquivo.
**Exemplo**:

Um arquivo de Professor armazenado em um disco com blocos de ***t = 4KiB*** , onde: ***r = 185B*** e ***n = 10.000***, assim temos:

* **Quantidade de registros por bloco**:
    * ${F = \left \lfloor \frac{4 \times 1024 B}{185 B} \right \rfloor = \left \lfloor 22,14...\right \rfloor = 22}$

* **Espaço inutilizado**:
    * ${U = 4096 - (22 \times 185) = 26B}$

* **Quantidade de blocos por arquivo**: 
	* ${B = \left \lceil \frac{10.000}{22} \right \rceil = \left \lceil 454,54...\right \rceil = 455}$

* **Consumo de espaço**:
	* ${C = 455 \times 4 KiB = 1.820 KiB = \frac{1820}{1024} MiB \approx 1,78 MiB}$

Tipicamente dados são organizados como **arquivos de registros**:

* **Registro** → coleção de valores relacionados a fatos sobre o minimundo, tais como atributos, instâncias de entidades e relacionamentos.

* **Arquivo** → coleção de registros relacionados

Registros devem ser organizados de forma a serem rapidamente localizados, garantindo a eficiência da interação com o BD.

Na memória, o banco não sabe como os dados estão armazenados, pois sua única função é armazená-los. Dessa forma, um arquivo possui um **cabeçalho (descritor)**, que contém os metadados úteis aos programas que realizam a desserialização os acesso aos registros.

* Ordem, tipo, e tamanho dos campos dos registros.
* Endereços dos blocos de armazenamento dos registros do arquivo.
* Códigos de caracteres especiais como separadores de campos.

### ${\color{orange}\text{ Arquivos de Registros }}$

Cada valor de um registro está restrito a um tipo de dado, sendo que o número de bytes para cada tipo é fixo, dependendo do sistema computacional
* Booleano: 1 byte
* Inteiro: 4 bytes
* Número real: 4 bytes
* Inteiro longo: 8 bytes
* Data: 10 bytes (formato DD-MM-AAAA)
* Data (Epoch Day): 4 bytes
* String de tamanho variável: n bytes
* *BLOB*: p + n bytes, onde p é o tamanho do ponteiro no registro para o endereço de bloco onde o objeto binário de tamanho n está armazenado

Arquivos podem ser compostos por registros de tamanho:

* **Fixo** → registros de mesmo tamanho
* **Variável** → registros de tamanhos diferentes
* **Campos de tamanho variável** → VARCHAR, TEXT
* **Campos opcionais** → NULL
* Campos multivalorados
* Arquivos mistos com registros de instâncias de entidades diferentes (incomum)

Um arquivo é alocado em diferentes blocos de disco, sendo que seus registros podem estar alocados em um ou vários blocos.

* **Não Espalhado** → o registro não pode atravessar o limite de um bloco.
* **Espalhado** → o registro é armazenado em múltiplos blocos
* Utiliza ponteiro no fim de cada bloco apontando para o bloco de continuidade do registro.

### ${\color{orange}\text{ Métodos de Acesso }}$

As principais operações que são aplicadas aos arquivos são:

* **Recuperação** → localização de registros em arquivo para que valores de campos possam ser lidos e processados, sem que haja alteração nos dados.

* **Atualização** → alteração de arquivo pela inserção ou exclusão de registros, ou ainda pela modificação de valores de campos de registros.

Determinados pela frequência de atualização de arquivos, tem-se:

* **Arquivos Estáticos** → operações de atualização são raramente executadas.

* **Arquivos Dinâmicos** → mudam com frequência de forma que operações de
atualização são constantemente executadas.

Muitas das operações aplicadas à arquivos envolvem algum tipo de pesquisa (consulta relacional).

* Especificando os critérios que determinados registros devem satisfazer.

* Envolvimento de expressões booleanas e/ou cálculos algébricos.

* Expressões podem apresentar diferentes graus de complexidade, como visto em álgebra relacional e fundamentos de SQL.

SGBDs acessam registros utilizando operações representativas, em que, tipicamente um registro é processado por vez.

* **Open** → preparação de arquivo para leitura ou escrita
    * Alocação de buffers para blocos
    * Recuperação do cabeçalho do arquivo
    * Posicionamento do ponteiro de arquivo no início do arquivo
* **Reset** → posiciona o ponteiro do arquivo aberto para o início do arquivo
* **Close** → libera buffers alocados e realiza operações de limpeza de memória

Das operações representativas que temos para os métodos de acesso são:

* Transfere o bloco que contém o registro para um buffer alocado e posiciona o ponteiro de arquivo no registro, tornando-o o registro atual:
    * **FIND (LOCATE)** → procura o primeiro registro que satisfaça uma condição
    * **FIND NEXT** → procura o próximo registro que satisfaça uma condição

* Posiciona o ponteiro no próximo registro, tornando-o o registro atual:
    * **READ (GET)** → copia o registro do buffer para uma variável de programa

* Transfere o registro do buffer de volta ao bloco no disco:
    * **DELETE** → remove o registro atual
    * **MODIFY** → modifica valores de campos do registro atual

* Localiza o bloco onde o registro deve ser inserido, transfere o bloco para um buffer, escreve o registro no buffer, transfere o buffer de volta ao bloco no disco:
    * **INSERT** → insere um novo registro no arquivo

* **Dada uma condição é especificada**: se o ponteiro de arquivo estiver posicionado no início do arquivo, reposiciona-o no primeiro registro que satisfaça a condição. Ou então, se o ponteiro de arquivo estiver posicionado em algum registro, reposiciona-o no próximo registro que satisfaça a condição. **Caso contrário**: se o ponteiro de arquivo estiver posicionado no início do arquivo, reposiciona-o no primeiro registro. Ou então se o ponteiro de arquivo estiver posicionado em algum registro, reposiciona-o no próximo registro.
	* **SCAN** → combinação das operações *Find*, *FindNext* e *Read*

Existem operações representativas de nível mais alto que podem ser aplicadas a conjuntos de registros:

* **FIND ALL** → procura o conjunto de registros que satisfaça uma condição.
* **FIND ORDERED** → procura, em uma ordem específica, o conjunto de registros
que satisfaça uma condição.
* **FIND N** → procura os N primeiros registros que satisfaçam uma condição.
* **REORGANIZE** → reorganiza os blocos e registros de um arquivo.

### ${\color{orange}\text{ Tipos de Arquivos }}$

Métodos de acesso operam de maneiras diferentes dependendo da forma como os arquivos são organizados, especialmente de como os registros encontram-se dispostos dentro dos arquivos.

Essas disposições podem estar na forma de:

* **Arquivo Heap (Pilha)** → registros posicionados sem ordem, com novos registros acrescentados ao final do arquivo.
	* **Pesquisa** → linear, varrendo todos os registros do arquivo no pior caso
		- O endereço do primeiro bloco do arquivo é recuperado do cabeçalho, cada bloco é copiado para um buffer, onde deve-se verificar se cada registro do bloco satisfaz os critérios de pesquisa. Assim a complexidade pe *O(n)*.
	* **Inserção** → registro arquivado na ordem em que é inserido
        - O endereço do último bloco do arquivo é recuperado do cabeçalho, o bloco é copiado para um buffer, onde o novo registro é acrescentado, e o buffer é copiado de volta ao bloco.
	* **Alteração** → pode resultar em exclusão seguida de inclusão, caso o registro aumente de tamanho
		- O endereço do bloco do arquivo é recuperado via pesquisa, depois copiado para um buffer, onde o registro é modificado, e o buffer é copiado de volta ao bloco.
	* **Exclusão** → efetuada diretamente ou por marcação
		- O endereço do bloco do arquivo é recuperado via pesquisa, depois o registro é removido, inserido novamente ao bloco (**exclusão direta**). Ou então, cada registro possui um byte extra, denominado marcador de exclusão, bastando apenas modificá-lo (**exclusão lógica ou de marcação**).

* **Arquivo Direto (Relativo)** → arquivo heap com registros de tamanho fixo, não espalhados, com blocos em alocação contígua.
	* Acesso simples a qualquer registro pela posição relativa no arquivo.
	* Não ajuda na pesquisa baseada em critérios.
	* Facilita a construção de índices no arquivo.

* **Arquivo Sequencial** → registros posicionados ordenadamente por um ou mais campos, denominados campos de ordenação
	* Blocos em cilindros contíguos
	* **Pesquisa** → binária, varrendo pequena quantidade de registros se a pesquisa for feita com operadores < ≤= > ≥ sobre os campos de ordenação
	  	- Blocos intermediários são recuperados e segmentos são descartados até se encontrar registros que satisfaçam os critérios de pesquisa.
		- **Complexidade** → O(lg n ), onde n é o número de blocos do arquivo
	* **Inserção** → registro deve ser inserido na posição correta
		- Pesquisa bloco, desloca os registros para as posições subsequentes, insere novo registro no espaço disponibilizado e gravar de volta para o disco.
	* **Alteração** →dependente da condição de pesquisa e do campo a ser alterado
		- Pesquisa bloco (binária para campos de ordenação ou sequencial), cópia para buffer, se o campo de ordenação não foi alterado, modifica-se o registro, mas se este foi alterado, deslocam-se registros gravando todos os blocos modificados.
	* **Exclusão** → igualmente dependente da condição de pesquisa

* **Arquivo Hash** → registros posicionados a partir da aplicação de uma função hash sobre um ou mais campos, denominados campos hash
	* **Pesquisa** → ótima para critérios de igualdade de chaves, complexidade O(1).
    * **Inserção** → pode gerar colisão e necessidade de expansão de arquivo
        - Aplica-se a função hash sobre o campo hash para calcular o endereço do bloco, depois de copiado para o buffer, o novo registro é acrescentado, e o buffer é copiado de volta ao bloco.
    * **Alteração** → dependente da condição de pesquisa e do campo alterado
	    - Se o campo hash não for modificado, modifica-se o registro no buffer, copiando o buffer de volta ao bloco. Se o campo hash for modificado, desloca-se o registro para outro bloco gravando os dois blocos modificados.
    * **Exclusão** → igualmente dependente da condição de pesquisa
    * Funções hash podem ser implementadas de formas diferentes
	    - Idealmente devem ser mantidas em memória primária, tornando muito eficiente o mapeamento de valores.
	    - Implementações robustas distribuem valores de maneira uniforme, consumindo pouca memória primária.
    * Existem dois problemas muito comuns em implementações hash:
	    - **Colisão** → diferentes valores são mapeados para o mesmo endereço, que já pode estar ocupado.
	    - **Expansão** → não há mais endereços disponíveis para armazenamento de registros e o espaço de endereçamento precisa ser expandido.
    * **Hashing Universal** → mapeia conjunto de chaves de tamanho variável para espaço de tamanho m , tal que a probabilidade de colisão é 1/m
    * **Hashing Perfeito** → mapeia conjunto fixo de chaves para espaço de tamanho m , tal que não haja colisão
