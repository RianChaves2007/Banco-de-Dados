# HO04: Álgebra Relacional I

## Conceitos Iniciais

É uma linguagem formal para todo modelo relacional, representando um conjunto de operações que manipulam bancos de dados relacionais.

A consulta ou interação ocorre por meio da declaração de dados especificados por uma sequência de operações algébricas a fim de solicitar uma recuperação desses dados. Dessa forma, o resultado de uma consulta será uma nova relação, ou seja, uma nova tabela.

A álgebra relacional é a base para as linguagens de consulta, e o SQL incorpora seus principais conceitos, na prática, para bancos de dados relacionais.

As operações realizáveis em álgebra relacional possuem multiplicidade, em que, quando aplicadas uma relação são chamadas de unárias, quando aplicadas em duas relações são binárias e para mais de duas relações, se tornam uma agregação que resume os dados relacionados.

## Condicional (σ) para uma relação (R) 

Serve para filtrar tuplas (linhas) mediante determinada condição, expressada por meio de operadores lógicos e aritméticos.

**Notação**: σ<sub> CONDICIONAL </sub>(R)

**Operadores condicionais**: < ≤ = ≥ > ≠

**Operadores lógicos**: ∧ ∨ ¬

**Exemplos**:

**PROFESSOR** \
| <u>CPF</u> | NOME | SEXO | SALARIO | DEPARTAMENTO |

* σ<sub> SEXO = ‘F’ </sub>(PROFESSOR)

Resulta em uma nova relação com todos os professores cujo sexo seja igual a ‘F’ (feminino).

* σ<sub> SEXO = ‘M’ ∧ SALARIO > 3000.00 </sub>(PROFESSOR)

Resulta em uma nova relação com todos os proferres do sexo masculino que tenham salário maior que 3000.00.

**Observações**: uma condicional é aplicada a cada tupla individualmente, ou seja, é uma operação unitária (**complexidade O(n)**). Entretanto pode-se associar diferentes operações de seleção, e tal abordagem é de caráter comutativo, isto é, a ordem da seleção não interfere no resultado.

σ<sub>COND1</sub>(σ<sub>COND2</sub>(R)) = σ<sub>COND2</sub>(σ<sub>COND1</sub>(R)) = σ<sub>COND1 ∧ COND2</sub>(R)

Apesar de não fazer diferença, existem casos em que a depender dessa ordem de uma operação, a complexidade aumenta.

## Projeção (π) de uma relação (R) 

Serve para filtrar os atributos de uma relação (colunas). Quando falamos de tuplas, falamos de linhas, linhas representam os registros de uma relação. Quando falamos de atributos, falamos de colunas de uma relação específica.

Nesta operação os atributos que não são especificados na projeção são descartados da relação resultante.

A relação resultante é o conjunto de atributos R explicitamente especificados e aparecem na mesma ordem. Essa operação possui **complexidade O(n)**.

**Notação**: π<sub> ATRIBUTOS </sub>(R)

**Exemplos**:

**PROFESSOR** \
| <u>CPF</u> | NOME | SEXO | SALARIO | DEPARTAMENTO |

* π<sub> NOME, SALARIO </sub>(PROFESSOR)

A relação resultante é uma tabela de duas colunas, nome e salário, de cada professor da relação original.

* π<sub> DEPARTAMENTO, SEXO </sub>(PROFESSOR)

A relação resultante é uma tabela de duas colunas, departamento e sexo, de cada professor da relação original.

**Observações**: quando houver tuplas repetidas, a relação resultante eliminará uma delas. A projeção efetua um custo computacional de O(n), da mesma forma que a operação de seleção. e assim como tal é uma operação unária, aplicável somente a uma relação. Mas diferentemente, a projeção não pode ser comutativa.

π<sub> ATR1 </sub>(π<sub> ATR2 </sub>(R)) ≠ π<sub> ATR2 </sub>(π<sub> ATR1 </sub>(R))

## Sequência de operações (σ + π)

Em resumo a seleção efetua uma operação de exclusão de linhas, e a projeção efetua uma operação de exclusão de colunas. Essas operações podem ser associadas em uma mesma expressão. É válido colocar que a ordem escolhida para executá-las pode determinar a eficiência da operação.

**Expressão em linha**:

* π<sub> ATRIBUTO </sub>(σ<sub> CONDICIONAL </sub>(R))

**Relações intermediárias**:

* A ← σ<sub> CONDICIONAL </sub>(R)
* B ← π<sub> ATRIBUTO </sub>(A)

## Renomear (ρ) uma relação (R) e seus atributos

Resulta em uma relação renomeada juntamente com seus atributos, tendo-se, também, a opção de renomear apenas a relação ou seus atributos.

**Notação**: ρ<sub> S(ATRIBUTOS) </sub>(R)

ρ<sub> (ATRIBUTOS) </sub>(R) → renomeia apenas os atributos
ρ<sub> S </sub>(R) → renomeia apenas a relação

**Exemplo**:

**PROFESSOR** \
| <u>CPF</u> | NOME | SEXO | SALARIO | DEPARTAMENTO |

* ρ<sub> TEACHER(CPF, NAME, GENDER, SALARY, DNUM) </sub>(PROFESSORES)

Resultado:

**TEACHER** \
| <u>CPF</u> | NAME | GENDER | SALARY | DNUM |

**Observações**: uma outra forma de alterar o nome é por meio de relações intermediárias. Além disso, a **complexidade de uma alteração de nome é O(1)**.

S<sub> (ATRIBUTOS) </sub> ← R

E ainda é possível renomear o resultado de uma operação, ou seja, a nova relação.

S<sub> (ATR1, ATR2) </sub> ← π<sub> ATR1, ATR2 </sub>(R)

S<sub> (ATR1, ATR2, ATR3, ATR4, ATR5) </sub> ← σ<sub> CONDICIONAL </sub>(R)

## Produto Cartesiano de duas relações (R1 ✕ R2)

A função desta operação é combinar tuplas de duas relações. A relação resultante possui tanto os atributos de R1 quanto os atributos de R2, além disso, as tuplas dessa relação resultante são todas as combinações possíveis entre as tuplas de R1 e de R2.

O número de colunas (atributos) da relação resultante será a soma do número de atributos das relações envolvidas, enquanto o número de linhas (tuplas) será o produto cartesiano entre elas.

**Exemplo ilustrativo**:

**R1**
| 1 2 3 |
|:-----:|
| a b c |
| d e f |
| g h i |

**R2**
| 4 5 |
|:---:|
| w x |
| y z |

**R1 ✕ R2**
| 1 2 3 4 5 |
|:---------:|
| a b c w x |
| d e f w x |
| h i j w x |
| a b c y z |
| d e f y z |
| h i j y z |

**Observações**: nem sempre tudo aquilo que uma linguagem oferece deve ser utilizada, existem operações, como a de produto, cujo custo computacional é alto, nesse caso a **complexidade geralmente é O(R ✕ S)**. Esta operação deve ser utilizada com cuidado. Entretanto, a depender da forma como a operação é implementada, a complexidade pode variar para valores mais reduzidos. 

## Junção (⋈) de duas relações

É equivalente a realizar uma combinação de duas relações juntamente com uma condicional.

A relação resultante é composta pelas tuplas combinadas de R1 e R2 que respeitam a condição imposta.
Quando a tupla não respeita a condição de junção o que os valores usados na condição sejam NULL, são descartados da relação resultante.

**Notação**: R1⋈<sub> CONDICIONAL </sub>R2

A equivalência seria: σ<sub> CONDICIONAL </sub>(R1 ✕ R2)

**Exemplo**:

**PROFESSOR** \
| <u>CPF</u> | NOME | SEXO | SALARIO | DEPARTAMENTO |

**DEPARTAMENTO** \
| <u>NUMERO</u> | NOME |

* PROFESSOR⋈<sub> DEPARTAMENTO = NUMERO</sub>DEPARTAMENTO

O resultado é uma relação que junta professores e departamentos desde que o atributo DEPARTAMENTO de professor seja igual ao atributo NUMERO de departamento. Estabelecendo-se assim, uma relação de sentido para além da junção.

Esse tipo de junção é denominado **equijunção**, quando há uma condicional com o operador de igualdade.

Além disso existe uma outra forma de junção denominada **junção natural**.

**Exemplo**:

**PROFESSOR** \
| <u>CPF</u> | NOME | SEXO | SALARIO | DEPARTAMENTO |

**DEPARTAMENTO** \
| <u>NUMERO</u> | NOME |

* PROFESSOR<sub>*</sub>DEPARTAMENTO

O resultado da **junção natural** de professores e departamentos acontecem com os seus respectivos atributos renomados da mesma forma, neste caso o atributo NOME.

É frequente que relações diferentes possuam atributos com o mesmo nome, entretanto realizar operações de junção pode acabar gerando problemas de ambiguidade.

Dessa forma, é recomendado o uso do **renomear (ρ)** para evitar esse tipo de problema.

**Exemplo**:

**PROFESSOR** \
| <u>CPF</u> | NOME | SEXO | SALARIO | DEPARTAMENTO |

**DEPARTAMENTO** \
| <u>NUMERO</u> | NOME |

* A<sub>(NUMERO, DNOME)</sub> ← π<sub> NUMERO, NOME (DEPARTAMENTO)</sub>
* RESULTADO ← PREOFESSOR⋈<sub> DEPARTAMENTO = NUMERO </sub>A

Resultado:

**RESULTADO** \
| CPF | NOME | SEXO | SALARIO | DEPARTAMENTO | NUMERO | DNOME |

E as tuplas da relação resultante respeitam a condição do departamento do professor ser o mesmo que o número do departamento.

## Agregação (γ) de tuplas de uma relação (R)

Serve para aplicar funções de agregação em atributos remanescentes de tuplas de uma relação.

A relação resultante possui os atributos de agregação é um atributo resultante de cada função de agregação.

### Funções de agregação

* CONT → contar número de tuplas agrupadas
* SUM → soma valores do atributo utilizado na função
* AVG → calcula a média dos valores do atributo utilizado na função
* MIN → captura valor mínimo dentre os valores do atributo utilizado na função
* MAX → captura valor máximo dentre valores do atributo utilizado na função

Se a **função de agregação não for renomeada**, o nome do atributo resultante será a concatenação entre o nome da função e o nome do atributo usado por ela.

**Exemplo**:
 
**PROFESSOR** \
| <u>CPF</u> | NOME | SEXO | SALARIO | DEPARTAMENTO |

* γ<sub> CONT(CPF), SUM(SALARIO) </sub>(PROFESSOR)

O resultado é uma relação de contagem de CPF e a soma total dos salários da relação professores.

* SEXOγ<sub> SUM(SALARIO), AVG(SALARIO) </sub>(PROFESSOR)

Apresenta a soma e a média dos salários dos professores do mesmo sexo.

## Sintaxe da Calculadora RelaX

A calculadora RelaX possui uma sintaxe baseada em álgebra relacional. É uma ferramenta didática, entretanto ela não substitui a linguagem formal apresentada anteriormente.

### Seleção

* σ a < b ∧ b ≠ c ( A )
* sigma a < b and b != c A

### Projeção

* π a, b ( A )
* pi a, b A

### Renomear

* σ x.a > 1 ( ρ x ( A ) )
* σ A.y > 2 ( rho y←a ( A ) )

### Junção cruzada ou produto

* ( A ) ⨯ ( B )

### Junção natural

* ( A ) ⋈ ( B )
* ( A ) ⋈ A.a ≥ B.a ( B )

### Agregação

* γ a, b; count(c)→c ( A )
* gamma count(a)->x, sum(b)->y ( A )

## Atividade do Hands-On

Especificar as seguintes consultas em álgebra relacional para recuperar os dados em um banco de dados relacional, considerando o conjunto de dados (dataset) denominado [IMDB-sample](https://dbis-uibk.github.io/relax/calc/gist/41cf5ce652756d9331eec7562644e074/imdbsample/0) disponível na [calculadora RelaX](https://dbis-uibk.github.io/relax/landing):

1. **Projetar o primeiro nome e o último nome dos atores de sexo feminino**

A operação é expressa por:

    π first_name, last_name (σ gender = 'F' (actors))

2. **Projetar o nome dos filmes com ano superior à 1999**

A operação é expressa por:

    π name (σ year>1999 (movies))

3. **Projetar o nome do filme e o nome do diretor de cada filme**

A operação é expressa por:

    -- junta filmes com a relação de filmes-diretores pelo id
    md = (movies) ⨝ id = movie_id (movies_directors)

    -- renomeia id da relação diretores
    d = ρ director_id←id (directors)

    -- junção natural de md com d
    mdd = md ⨝ d

    -- projeção
    π name, first_name (mdd)

4. **Projetar o nome do filme, nome do ator e o papel que cada ator teve no filme para filmes com ranking acima da nota 6**

A operação é expressa por:

    -- filmes com rank acima de 6
    m = σ rank > 6 (movies)

    -- junta filmes e papeis pelo id
    mr = m ⨝ id = movie_id roles

    -- renomeia id de atores para permitir junção natural
    a = ρ actor_id←id (actors)
    amr  = mr ⨝ a

    -- projeção
    π name, first_name, role (amr)


5. **Projetar o nome do diretor e o número de filmes que cada diretor dirigiu**

A operação é expressa por:

    -- agrupar número de filmes por diretor
    nfpd = γ director_id ; COUNT(movie_id)→nFilmes (movies_directors)

    -- juntar para obter número de filmes e nome dos diretores
    nfnd = (nfpd) ⨝ director_id = id (directors)

    -- projetar
    π first_name, nFilmes (nfnd)

6. **Projetar o gênero e o número de filmes de cada gênero**

A operação é expressa por:

    γ genre ; COUNT(movie_id)→nFilmes (movies_genres)


7. **Projetar o gênero, o ranking (nota) médio, mínimo e máximo dos filmes do gênero**

A operação é expressa por:

    -- juntar filmes com a relação filmes-gêneros
    fg = (movies) ⨝ id = movie_id (movies_genres)

    -- agregar rank por gênero
    γ genre ; AVG(rank)→medRank, MIN(rank)→minRank, MAX(rank)→maxRank (fg)
