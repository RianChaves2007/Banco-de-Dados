# HO03: Modelagem Relacional

## Conceitos Iniciais

### Modelo Relacional

É um conceito matemático e lógico criado por Edgar Codd que organiza os dados em relações (tabelas com linhas e colunas). Define regras para chaves primárias, chaves estrangeiras e integridade dos dados. Evita repetição de informações e garante que as ligações façam sentido.

### Diagrama de Esquema (DSC)

É a representação gráfica de tabelas, colunas, tipos de dados e ligações em um sistema. Ajuda a visualizar o projeto do banco de dados antes ou durante a criação. Facilita o entendimento de como as informações se conectam, estabelencendo entidades como relações.

OBS: Todo diagrama é uma simpleicação de algo que precisa ser representado de maneira específica, entretanto, não é possível representar tudo de maneira precisa. Dessa forma o DSC é um complemento do DER, que também não é capaz de ser mais preciso que a descrissão do minimundo.

## Construção de um DSC

Pode ser contruído a partir de um Diagrama Entidade-Relacionamento.

**1. Entidades Fortes**

        1.1 Criar uma relação para cada entidade forte, incluindo todos os atributos simples.
        1.2 Incluir apenas os atributos simples de uma tributo composto.
        1.3 Os atributos chave se tornam chave primária das relações (cada relação tem apenas uma chave primária).
        1.4 Se for escolhida uma chave composta, o conjunto dos atributos chave valem por uma chave primária.

**2. Entidades Fracas**

        2.1 Criar uma relação para cada entidade fraca e incluir seus atributos simples.
        2.2 Incluir como chave estrangeira, os atributos de chave primária da relação que corresponde à entidade proprietária.
        2.3 Escolha a chave estrangeira + um atributo chae parcial como chave primária da nova relação.

**3. Relacionamentos Binários 1:N**

        3.1 Incluir na entidade de participação do lado N, uma chave estrangeira correspondente à chave primária da outra entidade do relacionamento.

**4. Relacionamentos Binários N:N**

        4.1 Criar uma nova relação R3 para o relacionamento N:N
        4.2 R3 recebe como chaves estrangeiras as chaves primárias das entidades do relacionamento.
        4.3 A chave primária de R3 é a combinação de suas chaves estrangeiras.

**5. Relacionamentos Binários 1:1**

        5.1 Mesclagem: transformar as entidades em uma única relação.
        5.2 Chave Estrangeira: Mapear o relacionamento 1:1 como 1:N, escolhendo uma entidade para o lado N.
        5.3 Referência Cruzada: Maper o relacionamento 1:1 como N:N.
        5.4 Uma das três opções anteiores deve ser escolhida.

**6. Atributos Multivalorados**

        6.1 Cada atributo multivalorado se torna uma relação.
        6.2 A nova relação inclui o atrubuto + a chave primária da entidade ou relacionamento pertencente.

**7. Relacionamento de alto grau**

        7.1 Crie uma relação R3 para cada relacionamento n-ário, em que n>2
        7.2 Inclua como chave estrangeira em R3 as chaves primárias das relações que representam as entidades participantes
        7.3 A chave primária de R3 é a combinação de todas as chaves estrangeiras que referenciam as relações das entidades participantes

### Resumo

Em todas as relações, tem-se os atributos simples como atributos das relações (registros).

Na relação *FUNCIONÁRIO* tem-se *cpf* como chave primária e *cpfSupervisor* como chave estrangeira da relação recursiva com funconários supervisores (evita desperdício de memória se criassemos uma relação *SUPERVISOR*, por exemplo), e *siglaDepartamento* como chave estrangeira do relacionamento "alocacado" com a relação *DEPARTAMENTO*.

Na relação *DEPENDENTE*, tem-se *cpfFuncionário* como chave estrangeira para o relacionamento "possui", e *cpf* como chave prmária.

A relação *DEPARTAMENTO* possui *sigla* como chave primária e *cpfGerente* como chave estrangeira para o relacionamento "gerencia" com relação ao funcionário.

A relação *LOCAL* é criada por conta de um atributo multivalorado, possui chave primária composta por *cep* e *siglaDepartamento*, onde *siglaDepartamento* também é uma chave estrangeira.

A relação *TRABALHA* é criada por conta de um relacionamento complexo, possui *cpfFuncionário* + *siglaDepartamento* + *siglaProjeto* como chave primária composta, para a condição de "funcionário alocado".Possui *cpfFuncionário* e *siglaProjeto* como chaves estrangeiras simples, e *siglaDepartamento* + *siglaProjeto* como chave estrangeira composta. Dessa forma a relação guarda o atributos horas de um funcionário alocado em um departamento que está desenvolvendo um projeto.

A relação *PROJETO* possui *sigla* como chave primária. O atributo horas do projeto foi ocultado por ser um atributo derivado.

A relação *DESENVOLVIMENTO* é criada por conta de um relacionamento complexo, possui *siglaDepartamento* e *siglaProjeto* como chave primária composta e *siglaProjeto* como chave estrangeira. Essa relação guarda o atributo horas correspondentes ao desenvolvimento de um projeto no departamento.
