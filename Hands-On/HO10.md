## ${\color{orange}\text{Conceitos Iniciais}}$

### ${\color{orange}\text{Indexação}}$

A indexação envolve a construção de índices para acelerar a recuperação de registros em arquivos.

Um **índice de nível único** é uma estrutura auxiliar criada para acelerar a busca de registros em um arquivo de banco de dados, funcionando de maneira muito semelhante ao índice remissivo no final de um livro. 

Ele é composto por um arquivo menor e ordenado, onde cada entrada (registro do índice) contém apenas dois campos: a **chave de busca** (o valor procurado, como um CPF ou Código) e um **ponteiro** (o endereço físico indicando o bloco ou a linha exata no disco onde os dados completos estão armazenados).

Como esse índice é muito menor que o arquivo de dados original, ele pode ser carregado rapidamente para a memória RAM, evitando que o sistema tenha que ler o disco inteiro para encontrar um registro.

Existem duas abordagens principais para construir esses índices:

* **Indexação Densa** → o arquivo de índice contém **uma entrada para cada registro** existente no arquivo de dados.

	* A quantidade de registros é a mesma para a quantidade de índices que referenciam cada endereço de cada registro.
	* **Vantagem**: a busca é a mais rápida possível. Uma vez que você encontra a chave no índice, o ponteiro te leva diretamente ao registro final. O arquivo de dados principal não precisa sequer estar ordenado.
	* **Desvantagem**: os índices ocupam muito espaço em disco e na memória. Além disso, a manutenção é cara: toda vez que um registro é inserido ou deletado no banco de dados, o índice precisa ser atualizado.

* **Indexação Esparsa** → o arquivo de índice contém entradas para apenas alguns registros do arquivo de dados. Para que isso seja possível, o arquivo de dados principal deve obrigatoriamente estar ordenado com base na chave de busca.

	* Em vez de apontar para cada registro individual, o índice aponta apenas para o primeiro registro de cada bloco de disco (conhecido como registro âncora do bloco). Dessa forma o método de busca consiste em encontrar o “início de bloco” mas provável onde esteja o registro a ser encontrado, e após, realizar uma pesquisa no bloco de baixo custo em memória principal.
	* **Vantagem**: o arquivo de índice é muito menor, consome pouca memória e sofre menos impacto em operações de inserção ou exclusão, pois o índice só muda se o primeiro registro de um bloco mudar.
	* **Desvantagens**: a localização do dado é mais lenta que na indexação densa, pois exige acessar o bloco no disco e escanear os registros internamente até encontrar o alvo exato.


<center>

|Característica | Índice Denso | Índice Esparso |
|:-:|:-:|:-:|
| **Tamanho do arquivo de índice** | Grande (uma entrada por registro) | Pequeno (uma entrada por bloco de disco) |
| **Velocidade de localização** | Muito rápida (aponta direto para o dado) | Rápida (exige escanear o interior do bloco) |
| **Custo de Manutenção (Insert/Delete)** | Alto | Baixo |
| **Ordenação dos dados** | Não exige | **Obrigatório** (arquivo deve ser sequencial) |

</center>

O grande gargalo de qualquer SGBD não é o processamento, mas sim a leitura do disco físico (HD ou SSD). Ler um bloco do disco e trazê-lo para a memória RAM é uma operação extremamente lenta. No entanto, assim que um bloco inteiro (com todos os seus registos) é carregado na memória RAM, a pesquisa por um registo específico dentro desse bloco demora uma fração de segundo microscópica, sendo considerada irrelevante para o custo final. Por isso existem os métodos de indexação.

### ${\color{orange}\text{Índice Primário}}$

É um indice esparso com registros de tamanho fixo. O campo de inexação referencia a chave primária de um registro (lembrando que chaves primárias são índices únicos que apontam para um registro específico). Demanda que o arquivo indexado esteja ordenado pela chave primária. Haverá um registro de índice âncora para cada bloco do arquivo indexado.

#### ${\color{orange}\text{Exemplo 1}}$

Para um arquivo indexado esparso de Professor, com 10.000 registros de tamanho fixo de 185B, ordenado pela chave primária `CPF` e armazenado em um disco com blocos de 4KB, teremos:

* **Quantidade de registros por bloco**:

	* ${F = \left \lfloor \frac{4096 B}{185 B}\right \rfloor = \left \lfloor 22,14...\right \rfloor = 22}$
* **Quantidade de blocos por arquivo**:

	* ${B = \left \lceil \frac{10.000}{22}\right \rceil = \left \lceil 454,54...\right \rceil = 455}$

Pesquisas nesse arquivo demandam acessos a blocos de disco, como estão ordenados uma busca binária é a forma mais eficiente:

* O custo significativo, se dá pelo número de acessos que deverão ser feitos por bloco, que são processados pela RAM até encontrar o registro alvo. Aqui, o número de blocos do arquivo de dados é o número de índices aplicados na pesquisa.
	* ${\textit{Acessos} = \left \lceil \log_2(455)\right \rceil = \left \lceil 8,82...\right \rceil = 9}$

* Conclui-se que, para este arquivo, em no máximo 9 acessos um registro pode ser encontrado. Sabendo que a pesquisa foi realizada direto no arquivo indexado.

#### ${\color{orange}\text{Exemplo 2}}$

Para um índice primário criado sobre a chave primária `CPF` (do exemplo anterior) de 11B, onde o ponteiro de bloco ocupa 16B (*long*), teremos:

* **Quantidade de registros por bloco no arquivo de índices**:
	* ${F_i = \left \lfloor \frac{4096 B}{27 B}\right \rfloor = \left \lfloor 151,70...\right \rfloor = 151}$

* **Quantidade de índices por bloco no arquivo de índices**:
	* ${B_i = \left \lceil \frac{455}{151}\right \rceil = \left \lceil 3,01...\right \rceil = 4}$

* Pesquisas nesse arquivo só podem ser realizadas pelo campo de indexação e demandam acessos a blocos de disco, após encontrar o índice do bloco do registro no arquivo de indexação, uma única consulta ao arquivo de dados é realizada no bloco indexado.
	* ${\textit{Acessos} = \left \lceil \log_2(4)\right \rceil + 1 = 2 + 1 = 3}$

* Conclui-se que com 3 acessos é possível encontrar um mesmo registro, uma grande diferença com relação ao exemplo anterior.

Os arquivos de índices são significativamente menores que os arquivo indexados, ocupando
menos blocos em disco, como pôde ser visto nos exemplos. Pois:

* **Esparsidade** → garante menos registros no arquivo de índice.
* **Tamanho** → os registros de índice são menores que os registros do arquivo indexado (arquivo onde estão os dados).
* **Ordenação** → o arquivo ordenado permite pesquisa de complexidade logarítmica (*dividir para conquistar*).

As operações de atualização no arquivo indexado podem envolver **reordenação de registros** do próprio arquivo indexado e do arquivo de índice.

### ${\color{orange}\text{ Índices de Agrupamento }}$

O Índice de Agrupamento (ou **Clustering Index**) é uma estrutura de índice esparso utilizada quando o arquivo de dados está fisicamente **ordenado por um campo não exclusivo**, ou seja, um campo que pode conter valores repetidos, diferente de uma chave primária.

Funcionamento:

1.  **Agrupamento Físico no Disco**: o arquivo de dados está ordenado pelo campo de agrupamento.
	* Ex.: todos os professores do Departamento 1 ficam juntos no disco, seguidos por todos do Departamento 2, e assim por diante.

2. **Entradas no Índice**: diferente do índice primário (que cria uma entrada por bloco de dados), o índice de agrupamento cria exatamente um registro no arquivo de índice para cada valor distinto existente naquele campo.

3. **Ponteiro de Primeira Ocorrência**: a entrada de índice guarda o valor distinto (ex: Departamento 2) e um ponteiro que indica o bloco onde aquele valor aparece pela primeira vez no arquivo de dados. 

#### ${\color{orange}\text{ Exemplo }}$

No arquivo indexado de Professor, para um índice de agrupamento criado sobre
o campo `Departamento` de 8B, contendo 200 valores distintos, onde o ponteiro de
bloco ocupa 16B, teremos:

* **Tamanho do Registro do Índice**: Contém o campo *Departamento* ($8\text{B}$) $+$ o ponteiro de bloco ($16\text{B}$) = $24\text{B}$.

* **Fator de Bloco do Índice ($F_C$)**: Quantos registros de índice cabem num bloco de $4\text{KB}$ ($4096\text{B}$):

<div align="center">

$$F_C = \left \lfloor \frac{4096\text{B}}{24\text{B}} \right \rfloor = 170 \text{ entradas/bloco}$$

</div>

* **Número de Blocos do Arquivo de Índice ($B_C$)**: Como existem 200 valores distintos de departamento, precisamos de $200$ entradas no índice:

<div align="center">

$$B_C = \left \lceil \frac{200 \text{ entradas}}{170 \text{ entradas/bloco}} \right \rceil = \lceil 1,17 \rceil = 2 \text{ blocos}$$

</div>

* **Custo Total de Acesso ($A_C$)**:

	**1.** Busca binária dentro dos 2 blocos de índice: $\lceil \log_2 2 \rceil = 1$ acesso a disco.

	**2.** $+ 1$ acesso ao disco para ler o bloco do arquivo de dados onde a primeira ocorrência do departamento procurado foi encontrada.

	**3.** Total = 2 acessos a disco.

### ${\color{orange}\text{ Índices Secundário }}$

O índice secundário é um **índice denso** composto por registros de tamanho fixo. Ele é criado utilizando um campo de indexação que referencia um campo não ordenado no arquivo de dados principal. Por não exigir a ordenação física do arquivo indexado, a principal vantagem estrutural é a flexibilidade de se criar múltiplos índices secundários sobre o mesmo arquivo de dados.

* Exige a criação de um registro de índice para cada registro existente no arquivo indexado, contendo a chave de busca e um ponteiro referenciando o bloco onde o dado original se encontra no disco.
* É mantido fisicamente ordenado pela chave de indexação, o que permite a execução de pesquisas binárias sobre ele.
* Pesquisa demanda acessos aos blocos do arquivo de índice, somado a $+1$ acesso final ao disco para recuperar o registro no arquivo indexado.

Embora o arquivo de índice seja tipicamente menor que o arquivo indexado (pois os registros do índice são menores), a obrigatoriedade de possuir uma entrada por registro faz com que ele ocupe mais blocos do que um índice primário.

#### ${\color{orange}\text{ Exemplo }}$

No arquivo indexado de Professor, para um índice secundário criado sobre o campo `Departamento` de 8B, onde o ponteiro de bloco ocupa 16B, teremos:

* **Fator de bloco**: ${F_S = \left \lfloor \frac{4096 B}{24 B}\right \rfloor = \left \lfloor 170,66...\right \rfloor = 170}$

* **Blocos/Arquivo**: ${B_S = \left [ \frac{10.000}{170} \right ] = \left [ 58,82... \right ] = 59}$

* **Acesso à blocos no disco por pesquisa**: ${A = \left \lceil \log_2(59)\right \rceil + 1 = \left \lceil 5,88...\right \rceil + 1 = 6 + 1 = 7}$ 

### ${\color{orange}\text{ Comparação dos métodos de indexação }}$

<center>

| Característica | Índice Primário | Índice de Agrupamento | Índice Secundário |
|:-|:-:|:-:|:-:|
|**Tipo de Indexação** | Esparsa| Esparsa | Densa |
| **Ordenação do Arquivo de Dados** | Obrigatória | Obrigatória | Não obrigatória |
| **Campo de Indexação** | Chave Primária (Única) | Campo Não-Chave | Qualquer campo | 
| **Quantidade de Entradas no Índice** | Uma para cada bloco de dados | Uma para cada valor distinto | Uma para cada registro de dados | 
| **Limite por Arquivo** | Apenas um | Apenas um | Múltiplos |  

</center>
