# HO01: Fundamentos em Banco de Dados

## 1. O que é um sistema de banco de dados (SBD)?

Um Sistema de Banco de Dados (SBD) refere-se a um sistema computadorizado cujo objetivo principal é armazenar, gerenciar e disponibilizar dados de forma organizada, segura e estruturada, permitindo o acesso às informações por meio de aplicações e usuários.

## 2. Do que um SBD é composto?

Um SBD é composto fundamentalmente pelo conjunto de dados armazenados (Banco de Dados) e pelo programa que gerencia esses dados (Sistema Gerenciador de Banco de Dados - SGBD), além dos usuários/aplicações que com ele interagem.

`Banco de Dados + Modelo de Dados (lógica) + Software (SGBD) = SBD`

## 3. Como usuários e aplicações interagem com um SBD?

A interação entre usuários/aplicações e o SBD ocorre por meio da emissão de consultas (*queries*) ou requisições enviadas à camada lógica/gerenciadora. O SGBD processa tais requisições, valida as permissões de acesso e as regras de integridade e retorna o resultado correspondente.

## 4. O que é um banco de dados (BD)? Cite um exemplo de um BD, indicando o link onde seja possível encontrá-lo.

Um Banco de Dados (BD) é uma coleção organizada e coerente de dados logicamente relacionados, projetada para atender a um propósito ou contexto específico de determinado domínio de aplicação.

* **Exemplo**: O portal de Dados Abertos do Governo Federal do Brasil, que disponibiliza bases de dados públicas sobre orçamentos, saúde e educação.

* Link: https://dados.gov.br/

## 5. Quais são as propriedades de um BD?

As principais propriedades de um BD são:

* **Propósito específico**: É projetado e construído com um objetivo e público-alvo definidos.
* **Representação do Minimundo (Universo de Discurso)**: Representa um recorte ou abstração da realidade cujas alterações no mundo real se refletem no banco.
* **Coerência lógica**: Os dados são internamente consistentes e possuem um significado contextual explícito.
* **Compartilhamento e Concorrência**: É projetado para ser acessado e utilizado simultaneamente por múltiplos usuários e aplicações.

## 6. Quais são as etapas de um projeto de BD?

Na construção de um banco de dados, parte-se da abstração do minimundo até a implementação da estrutura lógica e física no SGBD.

* **Especificação de Requisitos**: Descrição completa do minimundo.
* **Análise de Requisitos**: Mapeamento das necessidades funcionais e regras de negócio.
* **Projeto Conceitual**: Modelagem de alto nível (estruturas e restrições), geralmente representada pelo Diagrama Entidade-Relacionamento (DER).
* **Projeto Lógico**: Mapeamento do modelo conceitual para o modelo do SGBD escolhido (ex.: modelo relacional com tabelas, chaves e colunas).
* **Projeto Físico**: Definição da estrutura de armazenamento interno no disco, índices, particionamento e caminhos de acesso.

## 7. O que é um sistema gerenciador de banco de dados (SGBD)?

É um software (ou conjunto de programas) especializado que fornece a infraestrutura necessária para definir, criar, manter, manipular e controlar o acesso a um Banco de Dados de forma segura e transparente.

## 8. Quais são as propriedades de um SGBD?

As principais características e recursos de um SGBD incluem:

* Suporte às Propriedades ACID (Atomicidade, Consistência, Isolamento e Durabilidade) em transações.
* Controle de Concorrência e Acesso Multiusuário.
* Gerenciamento de Segurança e Restrições de Integridade.
* Mecanismos de Backup e Recuperação contra Falhas.
* Independência de Dados e Controle de Redundância.
* Suporte a Múltiplas Visões de Dados e Linguagens de Consulta.

## 9. Indique situações em que o uso de SGBD pode se mostrar inadequado.

O uso de um SGBD tradicional pode ser inadequado em cenários como:

* Aplicações simples com poucos dados e acesso estritamente monousuário (onde arquivos locais ou planilhas resolvem o problema sem o *overhead* do SGBD).
* Sistemas de Tempo Real Rígido (Hard Real-Time), onde os atrasos do processamento de um SGBD inviabilizam os prazos estritos do sistema.
* Dispositivos embarcados com severas limitações de memória e hardware, que não suportam o peso de um motor de banco de dados.
* Situações em que os custos de licença, infraestrutura ou treinamento superam os benefícios do SGBD.

## 10. O que é um modelo de dados? 

É um conjunto de conceitos, ferramentas lógicas e abstrações que permite descrever a estrutura de um banco de dados (tipos de dados, relacionamentos e restrições), bem como as operações permitidas (inserção, remoção, atualização e consulta). O modelo define o paradigma segundo o qual os dados serão organizados (ex.: Relacional, Orientado a Objetos, NoSQL).

## 11. Em relação ao nível de abstração, quais são os tipos de modelos de dados?

Do maior para o menor nível de abstração:

1. **Modelo Conceitual (Alto Nível)**: Representa as estruturas de dados conforme a percepção do usuário final, focando em conceitos como entidades, atributos e relacionamentos, sem preocupação com implementação.
2. **Modelo Representativo / Lógico (Nível Intermediário)**: Detalha a estrutura para implementação no SGBD sem focar nos detalhes físicos do disco. Utiliza conceitos como tabelas, colunas, chaves primárias e tuplas (ex.: Modelo Relacional).
3. **Modelo Físico (Baixo Nível)**: Descreve como os dados são efetivamente gravados no meio de armazenamento, incluindo arquivos, blocos de memória, índices e estruturas de acesso.

## 12. O que é um Esquema de BD?

O Esquema de BD é a descrição ou estrutura lógica do banco de dados (metadados), especificada durante a **fase de projeto**. Ele raramente é alterado e define as tabelas, tipos de dados, restrições e relacionamentos do sistema.

## 13. O que é uma Instância de BD?

A Instância de BD é o conteúdo ou o conjunto de dados armazenado no banco em um determinado momento no tempo. Ao contrário do esquema, a instância varia constantemente à medida que novas informações são inseridas, atualizadas ou removidas a partir de um estado vazio/inicial.

## 14. Quais as vantagens de se adotar uma Arquitetura de Três Esquemas para implementar um BD?

A arquitetura de três esquemas divide a visualização do SBD em três níveis independentes. Suas principais vantagens são:

1. **Independência de Dados**: Permite alterar uma camada sem afetar as demais.
2. **Suporte a Múltiplas Visões**: Cada perfil de usuário/aplicação enxerga apenas a parcela de dados relevante ao seu contexto.
3. **Segurança Reforçada**: Oculta detalhes físicos e limita o acesso direto às estruturas internas do sistema.

## 15. Quais níveis existem em uma Arquitetura de Três Esquemas?

1. **Nível Externo (ou das Visões)**: Camada mais próxima dos usuários, composta por diferentes visões personalizadas da base de dados.
2. **Nível Conceitual**: Descreve a estrutura completa do BD para toda a comunidade de usuários (entidades, relacionamentos, restrições), ocultando detalhes do armazenamento físico.
3. **Nível Interno (Físico)**: Descreve a estrutura de armazenamento físico e os caminhos de acesso aos dados no disco.

## 16. O que é Mapeamento em uma Arquitetura de Três Esquemas?

É o processo de transformação de requisições e resultados entre os diferentes níveis da arquitetura. O SGBD realiza a tradução das consultas do Nível Externo para o Nível Conceitual e, em seguida, para o Nível Interno (Físico), garantindo que os dados corretos sejam recuperados do disco e entregues no formato esperado pelo usuário.

## 17. O que é Independência de Dados e qual sua importância para um SBD?

É a capacidade de modificar a definição do esquema em um nível da arquitetura sem a necessidade de alterar os esquemas nos níveis superiores ou as aplicações.

* **Independência Lógica de Dados**: Capacidade de alterar o esquema conceitual (ex.: adicionar uma tabela ou coluna) sem ter que alterar as visões externas ou os programas de aplicação.
* **Independência Física de Dados**: Capacidade de alterar o esquema interno/físico (ex.: reorganizar arquivos no disco ou criar índices) sem alterar o esquema conceitual.

## 18. O que é uma Linguagem de Consulta?

É uma linguagem de computador de alto nível utilizada pelos usuários ou aplicações para solicitar e recuperar informações de um banco de dados. A linguagem padrão do modelo relacional é a **SQL (*Structured Query Language*)**, que é predominantemente declarativa (não procedural), ou seja, o usuário especifica quais dados deseja, e o SGBD determina como buscá-los.

## 19. Cite as linguagens incorporadas na linguagem SQL.

O padrão SQL engloba sublinguagens especializadas:

* **DDL (*Data Definition Language* - Linguagem de Definição de Dados)**: Define e altera as estruturas do banco de dados (ex.: CREATE, ALTER, DROP).
* **DML (*Data Manipulation Language* - Linguagem de Manipulação de Dados)**: Manipula e consulta os dados armazenados (ex.: SELECT, INSERT, UPDATE, DELETE).
* **DCL (*Data Control Language* - Linguagem de Controle de Dados)**: Gerencia permissões e acessos de usuários (ex.: GRANT, REVOKE).
* **TCL (*Transaction Control Language* - Linguagem de Controle de Transação)**: Gerencia as transações no banco de dados (ex.: COMMIT, ROLLBACK).
* **VDL / SDL (*View / Storage Definition Languages*)**: Historicamente definidas separadamente, hoje a definição de visões (VDL) foi incorporada à DDL (CREATE VIEW), enquanto a definição de armazenamento (SDL) é tratada internamente pelo motor do SGBD ou por configurações físicas de infraestrutura.
